provider contract on the Linux 6.12.89 candidate.  It does not advance ACK,
replace a stock module, modify a supporting partition, weaken module loading,

## Provider oracle

The repaired oracle performs two independent checks:

1. every required ELF undefined symbol resolves to a real export from the
   candidate vmlinux or an exact stock module provider; and
2. every MODVERSIONS record matches the selected provider CRC.

Module exports are parsed only from `__ksymtab*`, `__kcrctab*`, and namespace
relocations.  Ordinary globally defined ELF symbols are not treated as kernel
exports.  The full provider inventory is in
`oos1610601-stock-export-provider-map.tsv`.

The exact `.601` population contains 1,021 modules: 985 normal/recovery/optional

## Root causes and compatibility repairs

### Eleven missing providers

Android commits `e460781091cd221c5f0de74529dd2df9f5f40bf2` and
`e76d0e53d029d00418b1256756872b9481704bc7` marked three file-descriptor
reservation methods and eight mutex/spinlock backend methods `#[inline]`.
The implementation remained present, but those wrappers were optimized out.
The stock `.601` Rust Binder binary directly imports the older mangled
providers.

The compatibility repair removes only those eleven later inline annotations
and adds exactly those eleven required names to the Oplus KMI symbol list.
The function bodies and signatures are unchanged.  All eleven providers are
now emitted and naturally reproduce the stock expected CRCs.

### Two formatting CRC mismatches

The stock and candidate compiler identity is the same, so this is not a Rust
toolchain or mangling transition.  Android commit
`e8665172af28140d5b4e08b2ff803b496237d28f` first passed AutoFDO profiling
flags to Rust.  With `CONFIG_AUTOFDO_CLANG=y`, those flags changed the DWARF
contract emitted for the compiler-generated `LowerHex::fmt` and
`UpperHex::fmt` providers even though their source signatures were unchanged:

- stock expected CRC: `0x1d23e0fd`
- plain candidate CRC: `0x831bf65f`
- compatibility candidate CRC: `0x1d23e0fd`

The repair sets `AUTOFDO_PROFILE_core.o := n`.  This excludes only Rust
`core.o` from AutoFDO profiling metadata and retains AutoFDO for the rest of
the kernel.  No CRC, `Module.symvers`, type string, or prebuilt module was
patched.

Android Common history through the current 6.12 LTS reference contains no
later repair for these exact source paths.

## Physical result

The exact candidate was written only to active `boot_a`; the complete
100,663,296-byte read-back matched the release image. Android reached
`sys.boot_completed=1`, user0 reached `RUNNING_UNLOCKED`, and `/data` mounted
as F2FS with `inlinecrypt`. The stock `rust_binder.ko` loaded normally; no
missing symbol, version disagreement, bad vermagic, invalid-module, signing,
or namespace failure was logged. TWRP, audio, camera, fingerprint, and NFC
operation were subsequently confirmed by the device owner.

The exact pre-test stock boot backup is retained under
`/home/travis/Android/kernel-test-backups/oos1610601-ack-6.12.89-rust-compat-retest-20260928-171544/`.
No supporting partition was modified.
