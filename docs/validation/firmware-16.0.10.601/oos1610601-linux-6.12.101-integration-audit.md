## Provenance

The authoritative Linux stable interval contains 595 commits and no merge
commits.  This branch imports 594 of those commits individually, retaining
their upstream authorship, subjects, bodies, and order.  Stable commit
`9e803a8767ef54f51dab1dcdba354420e77a7a4e` was already present with equivalent
or stronger pKVM MMIO-guard behavior and is recorded as `ALREADY_PRESENT`

The complete ordered inventory is in
`oos1610601-linux-6.12.98-to-6.12.101-commits.tsv`.  No stable interval was
squashed and the branch contains no merge commit for this update.

## Non-trivial conflict resolution

Linux stable commit `97a688563be71ec6fefc071aff69a66c69dbe244`,
`fscrypt: Avoid dynamic allocation in fscrypt_get_devices()`, conflicts with
the frozen Android `struct fscrypt_operations` contract and the local
hardware-wrapped-key path.

The imported commit uses the official Android Common backport
`ed9f54727ab32304aaa43ac8ad777e75ab0747d4`:

- the legacy `get_devices` callback remains at its original offset and type;
- the new stack-array callback consumes `ANDROID_KABI_RESERVE(1)` through
  `ANDROID_KABI_USE`;
- F2FS supplies the new callback without a dynamic allocation;
- fscrypt key destruction always evicts the key before freeing it; and
- the existing OnePlus hardware-wrapped-key selection remains unchanged.

This retains the stable use-after-free fix without changing the stock-visible
legacy callback layout.  No CRC, vermagic, MODVERSIONS, symbol-list, or ABI
reference workaround was used.

Stable commit `2419aa740810c659ddc17b9c639ea7d61ea74e28` was committed manually after a
host-side Git index-lock collision.  Its applied patch ID exactly matched the
authoritative stable patch; this was not a source conflict or semantic
adaptation.

## High-risk runtime areas

The interval changes 711 common-kernel files (11,472 insertions and 7,904
deletions in this downstream layout).  The following changes require explicit
static and physical attention:

- fscrypt/F2FS device enumeration and inline-encryption key eviction;
- the scoped kernel-credential series ending in
  `dm: avoid leaking the caller's thread keyring via the table device file`;
- DRM fixes, including Qualcomm-relevant shared GEM/TTM infrastructure;
- Bluetooth link accounting and cleanup;
- USB gadget and networking changes; and
- Rust compiler-lint compatibility.

There are no UFS or scheduler implementation commits in this stable interval.
The device-mapper credential change is security-relevant and remains present;
TWRP decryption is the mandatory first physical oracle.

## Required gates before physical testing

- production `//soc-repo:canoe_perf_dist` build;
- strict KMI, symtypes, enforced common ABI, and Canoe ABI review;
- the complete OOS 16.0.10.601 module oracle: 1,021 modules, 985 active and
  36 dormant, every hard ELF import resolved, and zero CRC/namespace failures;
- exact stock Rust Binder provider contract;
- preserved effective storage, signing, and local-feature configuration;
- Android boot-v4/AVB validation and exact image hashes; and
- unchanged stock `system_dlkm`, `vendor_dlkm`, `vendor_boot`, DTBO, VBMeta,
  metadata, and userdata.

Physical testing, if all static gates pass, is limited to `boot_a` with a
complete hash-verified backup and full partition read-back.  TWRP decryption
must pass before Android testing begins.
