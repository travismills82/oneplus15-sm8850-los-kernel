## Rust `bindings::bindings_raw::net`

Adding generic-netlink headers caused bindgen to emit the full private C
layout of `struct net` into the Rust bindings.  Rust uses the type only behind
pointers and passes those pointers to C helpers; no Rust source dereferences a
member.  The C layout itself is byte-identical between qualified 6.12.89 and
the candidate:

- size: 4160 / 4160
- alignment: 64 / 64
- BTF/pahole member diff: empty
- pointer representation: one 64-bit pointer in both builds

An initial `--opaque-type net` trial was rejected because bindgen represented
the type as a 4160-byte opaque blob rather than the qualified zero-sized
declaration.  The accepted repair blocklists only the bindgen `net` type and
provides the same private zero-sized `_unused[0]` declaration in the Rust
bindings and UAPI crates.  It does not change the global C definition.

The final STG representation of `bindings::bindings_raw::net` is identical to
the checked-in qualified record.  It is no longer present in the enforced ABI
diff.  The rebuilt `Module.symvers` is byte-identical to the pre-repair
candidate, so no exported symbol identity or CRC changed.

The relevant linked `Family::has_listeners` code still performs the same
range check, loads `init_net`, adds the family multicast offset, and calls
`netlink_has_listeners`.  Its linked instruction address materialization
changed after removal of bindgen-generated full-structure code, but argument,
return, pointer, branch, and call semantics are unchanged.

## `struct cfs_rq`

The scheduler correctness backport uses `ANDROID_KABI_REPLACE` so
`min_vruntime` and `zero_vruntime` intentionally occupy the same eight bytes.
Qualified and candidate BTF/pahole results prove:

- size: 512 / 512
- alignment: 64 / 64
- storage offset: 56 / 56
- storage width: 8 / 8
- every later member offset: identical
- `CONFIG_SCHED_CORE`: unset, so the `min_vruntime_fi` / `zero_vruntime_fi`
  counterpart is not present in this effective build
- scheduler source changed by this representation review: no
- zero-vruntime correctness behavior reverted: no

The qualified and candidate GENDWARFKSYMS `s#cfs_rq` records are already
token-identical, with SHA-256
`7f0a042c5dc256ecbe48131ce8933dbc8f8f7f18b501c000cfb55a705420d30f`.
Consequently, a leaf, anonymous-union, declaration-only, or type-string KABI
rule cannot change this enforced STG result: those rules transform the
GENDWARFKSYMS versioning input, while the enforced STG dump reads the actual
ELF/DWARF structure.  The actual DWARF necessarily contains the
`ANDROID_KABI_REPLACE` union.

Restoring the old raw-DWARF spelling would require removing or bypassing the
required source/runtime compatibility union, or masking the entire type in
the ABI reference/comparison.  Both are outside this authorization and would
weaken the evidence.  No such change was made.

After the valid Rust repair, the remaining transitive diff rooted in
`cfs_rq` is:

- changed functions: 6851
- changed variables: 107
- flattened changed types: 1712
- direct root types: 1 (`struct cfs_rq`)
